# 01. 개요

## 1. 배경

RS-422 신호를 광섬유로 장거리 전송하는 장비(RS-422 광 익스텐더)를 개발·검증하고 있다.

- RS-422 라인을 **샘플링**하여 SerDes(TLK1501)로 직렬화하고, SFP 광 모듈을 통해 전송한다.
- 원격측에서 복원된 샘플로 RS-422 신호를 재생한다.
- 장비는 **8채널** RS-422을 지원한다.
- 목표 최대 baudrate는 **8 Mbps**, 목표 fiber 길이는 **1 km**다.

장거리 전송이므로 링크를 통과하는 데 걸리는 시간(latency)과, 샘플링 방식으로 인한 데이터 무결성을 확인해야 한다. 이 프로그램은 그 측정을 위한 PC 측 테스트 도구다.

## 2. 목적

PC에서 UART로 메시지를 보내고, 광 링크 원격측에서 되돌아온 에코를 수신할 때까지의 시간을 측정한다.

- 측정 대상: **send → echo 수신 완료** 까지의 왕복 지연시간(RTT)
- 부가 측정: 데이터 오류(바이트 불일치, 누락, 타임아웃), baudrate별 전송 가능 여부
- 결과: 회차별 latency, 통계(min / max / 평균 / 표준편차 / 백분위), 오류 집계

## 3. 개발 단계

| 단계 | USB-UART | 채널 | baudrate | 비고 |
|------|----------|------|----------|------|
| **1단계 (현재)** | CH340 (USB Full-Speed) | 1채널 | ~ 2 Mbps | CH340 최대 baudrate가 2 Mbps |
| **2단계 (예정)** | FT4232H 테스트보드 (USB High-Speed, UART 4개) | 4채널 | ~ 8 Mbps | FT4232H 최대 12 Mbaud |

1단계 구현 시에도 2단계를 고려해 다음을 지킨다.

- 측정 로직은 **포트 1개 단위**로 만들고, 다채널은 이것을 여러 개 실행하는 방식으로 확장한다.
- 특정 칩에 의존하는 코드를 쓰지 않는다 (pyserial 공통 API만 사용).
- 결과 데이터에 처음부터 채널 번호 필드를 둔다.

## 4. 시스템 구성

```
 [로컬측]                                                                [원격측]
 PC ─USB─ CH340 ─UART(TTL)─ MAX3490 ─RS-422─ TLK1501 ─ SFP ═══ fiber ═══ SFP ─ TLK1501 ─RS-422─ MAX3490 ─ Echo
            USB-UART          RS-422 트랜시버   샘플링+SerDes    광 모듈                                        (루프백)
```

| 구성요소 | 역할 |
|----------|------|
| CH340 / FT4232H | USB ↔ UART 변환 (PC 측 시리얼 포트). 1단계 CH340, 2단계 FT4232H |
| MAX3490 | 3.3 V 전이중(full-duplex) RS-422 트랜시버. UART(TTL) ↔ RS-422 차동 신호 변환 |
| TLK1501 | SerDes. RS-422 채널을 샘플링한 병렬 데이터를 고속 직렬 신호로 변환(8b/10b) |
| SFP | 전기 ↔ 광 변환 |
| fiber | 장거리 광 전송 구간 (목표 1 km) |
| Echo | 원격측 RS-422 출력을 입력으로 **배선 루프백**. 처리 지연 없이 비트 단위로 즉시 되돌아감 |

## 5. 측정 구성 (경로)

링크 자체의 지연만 분리하려면 PC·CH340 경로의 지연(baseline)을 먼저 측정해서 빼야 한다. 다음 세 가지 구성으로 측정한다.

| 구성 | 루프백 위치 | 측정되는 것 |
|------|-------------|-------------|
| **A. CH340 루프백** | CH340 TX–RX 직결 (TTL) | PC + USB + CH340 기준 지연 |
| **B. 로컬 RS-422 루프백** | 로컬 MAX3490 출력 → 입력 | A + MAX3490 왕복 |
| **C. 광 링크 전체** | 원격측 배선 루프백 | B + SerDes·SFP·fiber 왕복 + 원격 MAX3490 |
| **C0. 광 링크 (짧은 fiber)** | 원격측 배선 루프백, 패치 코드(수 m) 사용 | C에서 fiber 지연만 빠진 값 |

```
링크 왕복 지연   ≈ C − B
fiber 왕복 지연  ≈ C − C0    (1 km 목표 시 이론값 약 9.8 µs)
```

## 6. 기능 요구사항

| ID | 요구사항 |
|----|----------|
| F-01 | COM 포트 목록 조회 및 선택 (CH340 VID `0x1A86`, FTDI VID `0x0403` 식별) |
| F-02 | UART 파라미터 설정: baudrate, data bits, parity, stop bits, flow control |
| F-03 | 송신 메시지 설정: 길이(byte), 패턴(고정/증가/랜덤), 회차별 시퀀스 번호 포함 |
| F-04 | 반복 횟수, 송신 간격(interval), 수신 타임아웃 설정 |
| F-05 | 회차마다 send 시각 ~ echo 전체 수신 시각, 첫 바이트 도착 시각 측정 |
| F-06 | 수신 데이터와 송신 데이터 비교 (불일치·누락 시 오류로 기록) |
| F-07 | 타임아웃 발생 시 오류로 기록하고 다음 회차 진행 |
| F-08 | 통계 계산 및 표시 (min/max/mean/stdev/p50/p95/p99) |
| F-09 | 결과 저장 (CSV / Excel), 측정 구성(A/B/C)·시험 채널 번호·fiber 길이 기록 |
| F-10 | GUI(PyQt5)에서 실행·중지, 진행 상황 및 결과 표시 |
| F-11 | 단일 채널 측정: 1개 COM 포트로 장비의 1개 채널을 시험 (채널 번호는 기록용으로 입력) |
| F-12 | baudrate 스윕: 여러 baudrate로 자동 반복 측정하여 오류율·latency 비교 (1단계 ~2 Mbps, 2단계 ~8 Mbps) |
| F-13 | 측정 결과 비교: 구성 A/B/C/C0 결과를 불러와 차이(C − B, C − C0) 계산 |
| F-14 | **[2단계]** 4채널 측정: FT4232H의 4개 COM 포트를 장비 채널에 매핑하여 측정 |

## 7. 비기능 요구사항

- 측정 타이머 분해능: 1 µs 이하 (`time.perf_counter_ns()` 사용)
- 측정 중 GUI 갱신·파일 기록이 측정 타이밍에 영향을 주지 않도록 측정 루프는 별도 스레드에서 수행
- 특정 USB-UART 칩에 묶이지 않도록 pyserial 공통 API만 사용 (어댑터 교체 대비)
- 동봉된 Python 3.8.10 embedded 환경에서 추가 설치 없이 동작

## 8. 측정의 한계 (중요)

- CH340(USB Full-Speed)의 지연과 지터는 **수백 µs ~ 수 ms** 수준이다.
- 목표 1 km fiber의 왕복 지연은 약 **9.8 µs**로, USB 지터보다 훨씬 작다 ([02-measurement.md](02-measurement.md) 참고).
- 따라서 PC 측정의 한 회차 값으로는 링크 지연을 알 수 없다. **다수 회차의 평균 차이**로 추정하며, 1 km는 수만 회 측정이 필요한 **분해능 한계 근처**다 ([02-measurement.md](02-measurement.md) 3절).
- 링크 지연의 정확한 값은 **오실로스코프/로직 분석기 측정을 기준**으로 하고, PC 측정은 이를 확인하는 용도로 쓴다.
- 이 프로그램의 강점은 **장시간·다회차로 시스템 전체의 동작(오류, 지연 분포)을 확인**하는 데 있다.
- 1단계(CH340)는 2 Mbps까지만 시험할 수 있다. 4·6·8 Mbps는 2단계(FT4232H)에서 시험한다.
