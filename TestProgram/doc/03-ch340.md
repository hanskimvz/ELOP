# 03. USB-UART 어댑터 (CH340 / FT4232H)

## 1. 개요

| 항목 | 내용 |
|------|------|
| 제조사 | WCH (Nanjing Qinheng Microelectronics) |
| USB VID | `0x1A86` (PID는 모델별 상이, CH340 계열은 주로 `0x7523`) |
| USB 속도 | USB 2.0 Full-Speed (12 Mbps) |
| 지원 baudrate | 약 50 bps ~ 2 Mbps |
| Windows 드라이버 | WCH `CH341SER` (장치 관리자에서 "USB-SERIAL CH340 (COMx)"로 표시) |

> 정확한 사양은 사용 중인 칩(CH340G/C/E/K 등) 데이터시트를 확인한다.

## 2. Latency에 주는 영향

### USB 프레임 단위 전송

Full-Speed USB는 1 ms 프레임 단위로 스케줄링된다. 따라서 PC ↔ CH340 구간에서 **수백 µs ~ 수 ms** 의 지연과 지터가 발생하며, 짧은 메시지를 높은 baudrate로 보낼수록 UART 직렬 시간보다 USB 오버헤드가 latency를 지배한다.

### 수신 버퍼링

CH340은 UART로 들어온 데이터를 내부 버퍼에 모았다가 USB IN 전송으로 호스트에 넘긴다. 버퍼가 차거나 일정 시간이 지나면 전송하므로, 소량 데이터의 수신 지연은 칩 내부 동작과 호스트 폴링 주기에 좌우된다.

- FTDI 칩과 달리 사용자가 조절할 수 있는 "Latency Timer" 설정이 드라이버에 노출되지 않는다.
- 따라서 이 지연은 **루프백 기준 측정으로 실측하여 baseline으로 사용**한다.

### 광 링크 측정에서의 의미

이 시스템에서 CH340은 측정 도구 쪽의 일부다. CH340/USB의 지연·지터(수백 µs ~ 수 ms)는 측정하려는 광 링크 지연(fiber 1 km당 왕복 약 10 µs)보다 훨씬 크다. 그래서 다음 원칙을 지킨다.

- 링크 지연은 구성 B(로컬 RS-422 루프백)와 구성 C(광 링크 전체)의 **평균 차이**로 추정한다 ([02-measurement.md](02-measurement.md) 3절).
- B와 C는 반드시 **같은 CH340, 같은 USB 포트, 같은 설정**으로 측정한다.
- USB-UART 어댑터를 바꾸면 baseline(구성 A, B)을 다시 측정한다.

### 예상 측정 결과 경향

- 짧은 메시지(수 byte), 높은 baudrate: latency가 대부분 USB/드라이버 오버헤드 → ms 단위, 1 ms 간격의 계단형 분포
- 긴 메시지, 낮은 baudrate: UART 직렬 시간이 지배 → 이론값에 근접

## 3. 설정 시 주의사항

- **baudrate**: CH340은 내부 분주로 baudrate를 생성하므로 비표준 값에서는 오차가 생길 수 있다. 에코 대상과 동일한 값으로 설정하고, 고속(921600 이상)에서는 데이터 불일치 여부를 반드시 확인한다.
- **흐름 제어**: 광 링크로 RTS/CTS가 전달되지 않는다면 `rtscts=False`로 둔다. 루프백 구성에서도 흐름 제어를 끈다.
- **신호 레벨**: CH340의 UART 출력은 TTL 레벨이므로 MAX3490(3.3 V)과 전압 레벨을 맞춘다 (CH340 VCC 3.3 V 동작 또는 레벨 변환).
- **DTR/RTS 토글**: 포트 open 시 DTR/RTS가 변하면 일부 MCU 보드(Arduino 등)가 리셋된다. 에코 대상이 MCU 보드면 open 후 안정화 대기 시간을 두거나 `dtr`/`rts` 초기값을 설정한다.
- **드라이버 버전**: 드라이버 버전에 따라 latency 특성이 달라질 수 있으므로 측정 결과에 드라이버 버전을 기록한다.
- **COM 포트 번호**: 연결하는 USB 포트에 따라 바뀔 수 있으므로 VID/PID로 포트를 찾는다.

```python
from serial.tools import list_ports

ch340_ports = [p.device for p in list_ports.comports() if p.vid == 0x1A86]
```

## 4. 목표 baudrate(8 Mbps)와 1단계 CH340의 한계

장비의 목표 최대 baudrate는 **8 Mbps**지만, CH340의 최대 baudrate는 **2 Mbps**다.

| 구간 | 최대 속도 | 8 Mbps 시험 |
|------|-----------|-------------|
| CH340 (1단계) | 2 Mbps | **불가** |
| FT4232H (2단계) | 12 Mbaud | 가능 |
| MAX3490 | 10 Mbps | 가능 (여유 작음, 데이터시트의 skew·상승시간 확인) |
| 샘플링 + TLK1501 + SFP | 샘플링 클럭에 따라 결정 | [02-measurement.md](02-measurement.md) 4절 |

따라서 1단계(CH340)는 **2 Mbps까지** 시험하고, 2 Mbps 초과는 2단계 FT4232H 테스트보드에서 시험한다.

## 5. 2단계: FT4232H 테스트보드

| 항목 | 내용 |
|------|------|
| 제조사 | FTDI |
| USB VID / PID | `0x0403` / `0x6011` |
| USB 속도 | USB 2.0 High-Speed (480 Mbps) |
| UART | 4개 (Windows에서 COM 포트 4개로 표시) |
| 최대 baudrate | 12 Mbaud → 목표 8 Mbps 시험 가능 |
| Windows 드라이버 | FTDI VCP 드라이버 (pyserial로 그대로 사용) |

### CH340 대비 장점

- High-Speed USB는 125 µs 마이크로프레임을 사용하므로 Full-Speed인 CH340보다 USB 지연·지터가 작다. 1 km 링크 지연(약 10 µs)을 평균 차이로 추정할 때 필요한 측정 회차가 크게 줄어든다 ([02-measurement.md](02-measurement.md) 3절).

### 설정 시 주의사항

- **Latency Timer**: FTDI 드라이버의 기본값은 **16 ms**다. 장치 관리자 → 포트 속성 → 포트 설정 → 고급에서 **4개 포트 모두 1 ms**로 낮춰야 latency 측정이 의미가 있다. 측정 결과에 이 값을 기록한다.
- **baudrate 정확도**: 설정한 baudrate가 분주로 정확히 만들어지는지 FT4232H 데이터시트의 baudrate 계산식으로 확인한다. 고속에서는 수 %의 오차도 오류의 원인이 된다.
- **포트 매핑**: 4개 COM 포트 번호와 FT4232H 내부 채널(A/B/C/D), 장비 채널 번호의 대응을 고정해 둔다. pyserial의 `list_ports`에서 `location`·`serial_number`로 구분할 수 있다.
- **baseline**: CH340에서 측정한 구성 A/B 결과는 FT4232H에 쓸 수 없다. 어댑터를 바꾸면 baseline을 다시 측정한다.

### 프로그램 측 대응

- 포트 검색은 CH340(VID `0x1A86`)과 FTDI(VID `0x0403`)를 모두 표시한다.
- 측정 로직은 pyserial 공통 API만 사용하므로 어댑터를 바꿔도 측정 코드는 그대로 쓴다.
