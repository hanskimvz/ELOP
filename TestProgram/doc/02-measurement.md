# 02. Latency 측정 방법

## 1. Latency 정의

```
t0      = write() 호출 직전 시각
t_first = 에코 첫 바이트 수신 시각
t1      = 송신한 N 바이트가 모두 수신된 직후 시각
latency = t1 - t0
```

- 시각은 `time.perf_counter_ns()` 로 측정한다 (Windows에서는 QueryPerformanceCounter 기반, 단조 증가, sub-µs 분해능).
- "수신 완료"는 **송신한 바이트 수만큼 모두 받았을 때**로 정의한다. 첫 바이트 도착 시간(`t_first - t0`)도 함께 기록한다.

## 2. 지연 구성요소

측정 구성 C(광 링크 전체) 기준 왕복 경로는 다음과 같다.

```
PC → CH340 → MAX3490 → [샘플링·TLK1501 → SFP → fiber → SFP → TLK1501·복원] → MAX3490 → Echo
PC ← CH340 ← MAX3490 ← [복원·TLK1501 ← SFP ← fiber ← SFP ← TLK1501·샘플링] ← MAX3490 ←─┘
```

| 구간 | 크기 (대략) | 비고 |
|------|-------------|------|
| PC ↔ CH340 (USB, 드라이버, OS) | 수백 µs ~ 수 ms, 지터 큼 | **측정값을 지배**. 구성 A로 측정 |
| UART 직렬 전송 | baudrate·길이로 결정 | 아래 계산식 |
| MAX3490 (편도) | 수십 ns | 데이터시트 propagation delay |
| 샘플링 | 0 ~ 1 샘플 주기 | 엣지 위치 지터로 나타남 |
| TLK1501 SerDes + SFP (편도) | 수십 ~ 수백 ns | 데이터시트 TX/RX latency |
| fiber 전파 (편도) | 약 **4.9 µs/km** | 굴절률 n ≈ 1.47 기준 |

- UART 신호는 링크 안에서 **비트 단위로 실시간 중계**되므로, 링크 지연은 바이트 길이와 상관없이 일정한 시간 지연(offset)으로 나타난다.
- 원격측이 배선 루프백이므로 에코도 비트 단위로 바로 되돌아온다. UART 직렬 시간은 송신과 수신이 겹쳐서 **한 번만** 더해진다.

### 목표 구성(1 km)의 링크 왕복 지연 예상

| 항목 | 왕복 |
|------|-----:|
| fiber 1 km | 9.8 µs |
| MAX3490 × 4회 통과 | 수백 ns 이하 |
| 샘플링 + TLK1501 + SFP (양방향) | 1 µs 이하 (추정, 데이터시트·실측 확인) |
| **합계** | **약 10 ~ 11 µs** |

### fiber 전파 지연

| fiber 길이 | 편도 | 왕복 |
|-----------:|-----:|-----:|
| 1 km | 4.9 µs | 9.8 µs |
| 10 km | 49 µs | 98 µs |
| 20 km | 98 µs | 196 µs |
| 40 km | 196 µs | 392 µs |

### UART 직렬 전송 시간 (이론값)

1 바이트 = start 1 + data 8 + (parity 0/1) + stop 1/2 비트. 8N1 기준 10비트.

```
T_wire = N × (비트 수/byte) / baudrate
```

| baudrate | 1 byte (8N1) | 32 byte | 256 byte |
|---------:|-------------:|--------:|---------:|
| 9,600 | 1.042 ms | 33.3 ms | 266.7 ms |
| 115,200 | 86.8 µs | 2.78 ms | 22.2 ms |
| 921,600 | 10.9 µs | 0.35 ms | 2.78 ms |
| 2,000,000 | 5.0 µs | 0.16 ms | 1.28 ms |
| 8,000,000 | 1.25 µs | 40 µs | 0.32 ms |

### 이론 하한

```
latency_min ≈ T_wire + 링크 왕복 지연 + PC/USB 오버헤드
```

측정값 − (`T_wire` + fiber 왕복 지연) = PC/USB/장비 오버헤드. 결과 보고 시 이론값을 함께 표시한다.

## 3. 링크 지연을 분리하는 방법

USB 지터(ms)가 링크 지연(µs)보다 훨씬 크므로 다음과 같이 접근한다.

1. **같은 조건**(baudrate, 길이, interval, PC 상태)으로 구성 B와 C를 각각 다수 회차 측정한다.
2. `링크 왕복 지연 ≈ mean(C) − mean(B)` 로 추정한다.
3. 추정 정밀도는 평균의 표준오차로 판단한다.

```
SE = sqrt(σ_B² / n_B + σ_C² / n_C)
```

필요 회차 수 (B와 C를 같은 횟수 n으로 측정, σ_B ≈ σ_C ≈ σ):

```
n ≈ 2 × σ² / SE²
```

**목표 1 km(링크 왕복 약 10 µs) 기준**

| USB 지터 σ | 목표 SE | 필요 회차 (각 구성) | 소요 시간 (interval 10 ms 기준, 각 구성) |
|-----------:|--------:|--------------------:|------------------------------------------:|
| 300 µs (CH340 예상) | 2 µs | 약 45,000회 | 약 9 ~ 10분 |
| 300 µs | 1 µs | 약 180,000회 | 약 35 ~ 40분 |
| 50 µs (FT4232H 예상) | 1 µs | 약 5,000회 | 약 1분 |

- σ 값은 예상치다. 구성 A 측정으로 실제 σ를 먼저 확인하고 필요 회차를 다시 계산한다.
- 1단계(CH340)로도 1 km 링크 지연을 **대략(±2 µs 수준)** 확인할 수는 있지만 오래 측정해야 한다. 2단계(FT4232H, High-Speed USB)는 지터가 작아서 훨씬 유리하다.
- fiber 지연만 보려면 B 대신 C0(짧은 패치 코드)와 비교한다 (`C − C0`). SerDes 등 장비 지연이 상쇄되어 이론값 9.8 µs와 직접 비교할 수 있다.

> 평균 비교는 PC/USB 지연 분포가 B와 C 측정 사이에 변하지 않는다는 가정에 의존한다. B와 C를 번갈아 여러 번 측정해서 일관성을 확인한다.

### 정밀 측정 (교차 검증)

1 km 링크 지연(약 10 µs)의 **기준값은 이 방법으로 정한다.** 로컬측 MAX3490의 TX 입력과 RX 출력(TTL)을 오실로스코프/로직 분석기로 동시에 관찰하여, **송신 비트 엣지와 되돌아온 같은 엣지의 시간차**로 측정한다. 이 값은 USB 영향이 없어서 ns 단위 정밀도를 갖는다. PC 측정 결과는 이 값과 비교해 검증한다.

## 4. 샘플링 방식에 따른 신호 품질

RS-422 신호를 샘플링 클럭으로 샘플링해서 전송하므로, 수신측에서 재생된 신호의 엣지 위치는 최대 1 샘플 주기(`Ts`)만큼 흔들린다.

- 왕복 경로는 샘플링을 **2번**(로컬→원격, 원격→로컬) 거치므로 엣지 지터가 최대 약 `2 × Ts`
- UART 비트 폭 `T_bit = 1 / baudrate` 대비 지터 비율이 작아야 한다.

```
지터 비율 ≈ 2 × Ts / T_bit
```

| baudrate | T_bit | 50 MHz (Ts 20 ns) | 75 MHz (Ts 13.3 ns) | 150 MHz (Ts 6.7 ns) |
|---------:|------:|------------------:|--------------------:|--------------------:|
| 115,200 | 8.68 µs | 0.5 % | 0.3 % | 0.2 % |
| 921,600 | 1.085 µs | 3.7 % | 2.5 % | 1.2 % |
| 2,000,000 | 500 ns | 8 % | 5.3 % | 2.7 % |
| 4,000,000 | 250 ns | 16 % | 10.7 % | 5.3 % |
| **8,000,000** | **125 ns** | **32 %** | **21 %** | **10.7 %** |

(실제 샘플링 클럭은 TBD. 위 값은 예시)

**목표 8 Mbps 기준 검토**

- 8 Mbps에서 비트 폭은 125 ns뿐이라 샘플링 지터의 비중이 크다.
- 지터 비율을 10 % 이하로 유지하려면 `2 × Ts ≤ 12.5 ns`, 즉 **채널당 실효 샘플링 160 MHz 이상**이 필요하다.
- 여기에 MAX3490의 skew·상승/하강 시간, 송·수신 UART 간 baudrate 오차가 더해진다.
- 일반적인 UART 수신기는 비트 중앙에서 샘플링하므로 이론상 지터 여유는 이보다 크지만, 위 요인이 합쳐지므로 실측(baudrate 스윕)으로 확인해야 한다.

- 지터 비율이 커지면 수신 UART가 비트를 잘못 읽어 **바이트 오류**가 생긴다.
- 프로그램의 baudrate 스윕(F-12)으로 baudrate별 오류율을 측정해서 장비가 지원하는 최대 baudrate를 실측으로 확인한다.
- 1단계(CH340)는 **2 Mbps까지** 스윕한다. 4·6·8 Mbps 구간은 2단계(FT4232H)에서 시험한다 ([03-ch340.md](03-ch340.md) 4절).
- 같은 baudrate로 구성 A(어댑터 루프백)에서 오류가 0인지 먼저 확인한다. A에서 오류가 나면 장비가 아니라 어댑터 문제다.

## 5. 측정 절차

1. 포트 open 후 입력/출력 버퍼 초기화 (`reset_input_buffer()`, `reset_output_buffer()`)
2. 워밍업: 결과에 포함하지 않는 수 회 송수신 (드라이버·링크 상태 안정화)
3. 회차별 반복
   1. 수신 버퍼에 잔여 데이터가 있으면 비우고 경고 기록
   2. `t0` 기록 → `write(payload)`
   3. N 바이트가 모두 올 때까지 읽기 (첫 바이트 도착 시 `t_first` 기록)
   4. `t1` 기록
   5. 수신 데이터와 송신 데이터 비교
   6. 타임아웃 시 오류로 기록
   7. 설정된 interval 만큼 대기 후 다음 회차
4. 통계 계산 및 저장

## 6. 메시지 형식

회차 간 데이터 혼동(이전 회차의 지연 도착 데이터)을 구분하기 위해 페이로드에 시퀀스 번호를 넣는다.

```
[SEQ (4 byte, little-endian)] [PATTERN ... (N-4 byte)]
```

- 수신 SEQ가 현재 회차와 다르면 "순서 불일치" 오류로 기록한다.
- 패턴은 샘플링 오류를 잘 드러내도록 `0x55`/`0xAA`(엣지가 많은 패턴), 증가 패턴, 랜덤 패턴을 선택할 수 있게 한다.
- 길이가 4 byte 미만인 측정이 필요하면 SEQ를 생략하는 옵션을 둔다.

## 7. 읽기 방식과 측정 정확도

pyserial 읽기 방식에 따라 측정값 자체가 달라질 수 있다.

| 방식 | 특징 |
|------|------|
| `read(N)` + `timeout` | 구현 단순. 드라이버가 N 바이트를 모아 반환할 때까지 블로킹 |
| `in_waiting` 폴링 + `read(in_waiting)` | 첫 바이트 시각 기록 가능, 반응성 좋음. CPU 사용률 높음 |

- 기본은 `in_waiting` 폴링으로 정확도를 우선하고, 옵션으로 블로킹 방식을 선택할 수 있게 한다.
- 측정 루프 안에서 로그 출력·GUI 갱신·파일 쓰기를 하지 않는다. 결과는 메모리에 쌓고 큐로 전달한다.
- 8 Mbps에서는 약 1 MB/s가 들어오므로, 긴 메시지를 쓸 때는 pyserial 수신 버퍼(`set_buffer_size(rx_size=...)`)를 충분히 크게 잡는다.
- [2단계] 4채널 동시 측정 시 채널마다 폴링 스레드가 돌아 CPU 부하와 측정 지터가 커질 수 있다. latency 측정은 채널 순차 측정을 기본으로 하고, 동시 측정은 채널 간 간섭·오류 확인 용도로 쓴다.

## 8. 통계

| 항목 | 설명 |
|------|------|
| count / ok / timeout / mismatch / seq_error | 전체·성공·오류 유형별 횟수 |
| byte error rate | 오류 바이트 수 / 전체 송신 바이트 수 |
| min / max | 최소·최대 latency |
| mean / stdev / SE | 평균·표준편차·평균의 표준오차 |
| p50 / p95 / p99 | 백분위 (지터·꼬리 지연 파악) |
| histogram | 분포 확인용 (USB 1 ms 프레임에 따른 계단형 분포가 나타날 수 있음) |

latency 통계는 **성공 회차만** 대상으로 계산한다.

## 9. 정확도 확보를 위한 권장 사항

- Windows 전원 옵션을 "고성능"으로 설정 (CPU 절전 상태 전환에 의한 지터 감소)
- USB 허브를 거치지 않고 PC 포트에 직접 연결, USB 선택적 절전 해제
- 측정 중 다른 부하가 큰 프로그램 종료
- 구성 B와 C는 같은 PC·같은 USB 포트·같은 CH340으로 측정
